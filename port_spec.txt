1. 数据模型 (所有语言必须一致)
--------------------------------------------------------------------------------
棋盘：8x8 二维数组 board[row][col]。
  row 0 = 第 8 横线（黑方底线，屏幕上方）；row 7 = 第 1 横线（白方底线，下方）。
  col 0..7 = a..h 文件。
  大写字母 = 白方棋子：K Q R B N P
  小写字母 = 黑方棋子：k q r b n p
  '.' = 空格

GameState 字段：
  board[8][8]           字符棋盘
  whiteToMove          bool，true=白方走
  canCastleWK/WQ/BK/BQ bool，四方易位权
  enPassantRow/Col     int，过路兵目标格；无 = -1
  halfmoveClock        int，50步规则半步计数（吃子或动兵清零）
  fullmoveNumber       int，开局=1，每黑方走完+1
  history              string 列表（长式代数记谱，仅 recordHistory 时记录）
  positionKeys         string 列表（局面键历史，用于三次重复；初始局面须含 1 个）

Move 字段：
  fromRow fromCol toRow toCol  int
  piece     被移动棋子字符
  captured  被吃棋子字符（'.'=未吃；过路兵填被吃兵字符）
  special    见下枚举
  promotion  升变目标棋子字符（仅升变时有效，'.'=无）

SpecialMove 枚举：
  None=0, DoublePawn=1, EnPassant=2, CastleKingside=3, CastleQueenside=4, Promotion=5

Move.toString() 记谱规则（与 C++ Move::toString 完全一致）：
  - CastleKingside -> "O-O"；CastleQueenside -> "O-O-O"
  - 兵：file(fromCol) + toSquare；若吃子则前缀 file(fromCol)；升变追加 "=" + 大写升变子
  - 其它：大写(piece) + fromSquare + (吃子则 'x') + toSquare
  - toSquare = file(col) + (8 - row)；file(col)= "abcdefgh"[col]

2. 规则引擎 Rules (静态/模块函数)
--------------------------------------------------------------------------------
InBoard(r,c)            r,c ∈ [0,7]
IsWhitePiece(p)         p!='.' 且为大写
IsBlackPiece(p)         p!='.' 且为小写
IsPieceOfSide(p,white)  该棋子是否属于该方

IsAttacked(board, r, c, byWhite) -> bool
  单一例程，支撑整个规则库。检测 (r,c) 是否被 byWhite 方攻击：
  1) 兵攻击：白兵攻击其上方两斜格 (pr=r+1)，黑兵 (pr=r-1)；检查 (pr,c-1),(pr,c+1)
  2) 马攻击：8 个 L 偏移
  3) 王攻击：8 邻格
  4) 滑动射线：8 方向，前 4 个为直线(车/后)，后 4 个为斜线(象/后)；遇到首枚非空格，
     若为对应攻击子则返回 true，否则停止该射线。

GeneratePseudoMoves(state, r, c) -> Move[]
  仅按几何规则生成，不检验送王。按棋子类型分派：
  - 兵 GeneratePawnMoves：前进 1 格(空)；起始行(double: 白 row6->4, 黑 row1->3)可进 2 格
    (DoublePawn，过路兵目标格=(fromRow+toRow)/2)；斜吃敌子；若 (tr,tc)==(epRow,epCol)
    生成 EnPassant(被吃子填敌兵字符)。兵到达 row0/row7 时生成 4 种升变(Promotion,
    promo ∈ "QRBN"，黑方转小写)。
  - 马/王：固定偏移 GenerateOffsetMoves（王额外调用 GenerateCastlingMoves）
  - 象/车/后：滑动 GenerateSlidingMoves
  偏移表（务必与 C++ 一致）：
    马 dr=[-2,-2,-1,-1,1,1,2,2] dc=[-1,1,-2,2,-2,2,-1,1]
    王 dr=[-1,-1,-1,0,0,1,1,1]  dc=[-1,0,1,-1,1,-1,0,1]
    象 dr=[-1,-1,1,1]           dc=[-1,1,-1,1]
    车 dr=[-1,1,0,0]            dc=[0,0,-1,1]
    后 dr=[-1,1,0,0,-1,-1,1,1]  dc=[0,0,-1,1,-1,1,-1,1]
    滑动射线方向 dr=[-1,1,0,0,-1,-1,1,1] dc=[0,0,-1,1,-1,1,-1,1]
      （前4=直线，后4=斜线，与 IsAttacked 一致）

GenerateCastlingMoves(state, r, c, isWhite)：
  白王仅在 r=7,c=4；黑王仅在 r=0,c=4。
  白短易位：canCastleWK && b[7][7]=='R' && b[7][5]=='.' && b[7][6]=='.'
            且 7,4 / 7,5 / 7,6 均不被黑攻击。
  白长易位：canCastleWQ && b[7][0]=='R' && b[7][1..3]=='.'
            且 7,4 / 7,3 / 7,2 均不被黑攻击。
  黑短易位：canCastleBK && b[0][7]=='r' && b[0][5]=='.' && b[0][6]=='.'
            且 0,4 / 0,5 / 0,6 均不被白攻击。
  黑长易位：canCastleBQ && b[0][0]=='r' && b[0][1..3]=='.'
            且 0,4 / 0,3 / 0,2 均不被白攻击。
  生成对应 CastleKingside/CastleQueenside 走法。

GenerateLegalMoves(state, r, c) -> Move[]
  两阶段：先 GeneratePseudoMoves，对每步在 CloneLight() 副本上 ApplyMove(false)，
  再用 FindKing + IsAttacked 检验己方王是否仍被攻击；不安全则丢弃。

GenerateAllLegalMoves(state) -> Move[]
  遍历全盘，对本方(whiteToMove)所有棋子调用 GenerateLegalMoves 并合并。

ApplyMove(state, m, recordHistory=true)：
  1) board[to]=piece; board[from]='.'
  2) 特殊：
     DoublePawn -> epRow=(fromRow+toRow)/2, epCol=fromCol
     EnPassant   -> 移除被吃兵：capRow = (piece=='P'? toRow+1 : toRow-1); board[capRow][toCol]='.'
     CastleKingside -> board[fromRow][5]=board[fromRow][7]; board[fromRow][7]='.'
     CastleQueenside -> board[fromRow][3]=board[fromRow][0]; board[fromRow][0]='.'
     Promotion -> board[toRow][toCol]=promotion
  3) 若 special != DoublePawn，清空 epRow/epCol = -1
  4) 易位权：K 走 -> WK=WQ=false；k 走 -> BK=BQ=false；
     角格(0/7行,0/7列)的 from 或 to 命中则对应侧易位权=false
     （a1=7,0 / h1=7,7 / a8=0,0 / h8=0,7）
  5) 50步：动兵或吃子 -> halfmoveClock=0，否则 +1
  6) 若 !whiteToMove 则 fullmoveNumber++；翻转 whiteToMove；
     recordHistory 时 push history 与 GetPositionKey()

FindKing(board, isWhite) -> (r,c)（-1,-1 若不在）
IsInCheck(state, isWhite) -> bool：定位王，调用 IsAttacked(...,!isWhite)
IsCheckmate(state)    = IsInCheck(side) && 无合法走法
IsStalemate(state)    = !IsInCheck(side) && 无合法走法
IsFiftyMoveDraw(state)= halfmoveClock >= 100
HasLegalEnPassant(state)：若 epRow<0 返回 false；pawnRank=白?epRow+1:epRow-1，
  检查 epCol±1 是否有本方兵且存在 EnPassant 合法走法。
IsThreefoldRepetition(state)：positionKeys 末项出现 >=3 次。
IsInsufficientMaterial(state)：
  收集非王非空格子（区分黑白）。若存在 P/R/Q -> false。
  total=白非王数+黑非王数：
    0 或 1 -> true（KvK / K+单象/单马vK）
    2 -> 若双方各一子 -> true；若同侧两子：
        BB：两象同色格( (r+c)%2 相同 ) -> true，异色 -> false（可杀）
        NN -> true（双马和棋）；其它 -> false
    其它 -> false
  注意：K+兵/K+车/K+后 已在有 P/R/Q 时返回 false。

GetPositionKey(state)：64 格 + side(w/b) + 四方易位权(K/Q/k/q 或 '-') +
  若 HasLegalEnPassant 为真则 "epRow,epCol" 否则 "-1,-1"。
  （ep 格仅在存在合法吃过路兵时才编码，符合 FEN 标准）

Clone()：深拷贝全部字段含 history/positionKeys。
CloneLight()：同 Clone 但跳过 history 与 positionKeys（AI 搜索用）。

PieceIndex(p): P->1 N->2 B->3 R->4 Q->5 K->6 其它->0
GetPST(idx,pos): 按 idx 返回对应表[pos]

Evaluate(state) -> int（白方视角，正=白优）：
  for 每格 p:
    if p=='.' continue
    idx=PieceIndex(p); pos=r*8+c
    if 大写: score += PieceValue[idx] + GetPST(idx, pos)
    else:    score -= PieceValue[idx] + GetPST(idx, (7-r)*8+c)   // 黑取白表行镜像
  return score

EvaluateSide(state)：白方走返回 Evaluate，否则返回 -Evaluate（negamax 约定）

MoveOrderScore(m): 非吃子=0；否则 victim*10 - attacker（victim/attacker 用 PieceValue[PieceIndex]）
OrderMoves(moves): 按 MoveOrderScore 降序排序

Quiescence(state, alpha, beta, qdepth):
  stand = EvaluateSide(state)
  if stand >= beta return beta
  if stand > alpha: alpha = stand
  if qdepth >= 4 return alpha
  收集所有合法走法中的吃子着法，OrderMoves 后递归：
    score = -Quiescence(child, -beta, -alpha, qdepth+1)
    if score >= beta return beta
    if score > alpha: alpha = score
  return alpha

Negamax(state, depth, alpha, beta, ply):
  moves = GenerateAllLegalMoves(state)
  if moves.empty():
    if IsInCheck(side): return -MateScore + ply   // 被将死，离根越近越差
    return 0                                        // 逼和
  if depth <= 0: return Quiescence(state, alpha, beta, 0)
  OrderMoves(moves)
  best = -Infinity
  for m in moves:
    child = CloneLight(); ApplyMove(child, m, false)
    score = -Negamax(child, depth-1, -beta, -alpha, ply+1)
    if score > best: best = score
    if best > alpha: alpha = best
    if alpha >= beta: break
  return best

FindBestMove(state, depth) -> 可选 Move（无合法走法=None/nullopt/Option::None/None）：
  moves = GenerateAllLegalMoves(state)
  if empty: return None
  if size==1: return moves[0]
  OrderMoves(moves)
  bestMove=moves[0]; bestScore=-Infinity; alpha=-Infinity; beta=Infinity
  for m in moves:
    child=CloneLight(); ApplyMove(child,m,false)
    score = -Negamax(child, depth-1, -beta, -alpha, 1)
    if score > bestScore: bestScore=score; bestMove=m
    if score > alpha: alpha = score
  return bestMove

7. 跨语言驱动协议（JSON over stdio）—— 消除"引擎如何被外部驱动"的歧义
--------------------------------------------------------------------------------
§1–§3 定义的是引擎**内部**的规则库与 AI；§4 定义的是引擎**独立运行**的控制台 CLI。
但本仓库的 cross-language tournament（tournament/run_tournament.mjs）与 chess-cordis
harness 并不直接调用 CLI，而是以"子进程 + 逐行 JSON"方式驱动每个引擎。该协议此前
未写入规范，是移植/对弈一致性最大的歧义源。现固化如下（chess-cordis/drivers/* 与
tournament/js_driver.mjs 已对齐）：

启动：
  - 引擎进程启动后，必须向 stdout 打印第一行：{"ready":true}（UTF-8，单行）。
  - 若引擎未在宽限时间内打印 ready，harness 仍会继续（不强制依赖该字段）。

请求（harness → 引擎，stdin，逐行 JSON）：
  {"id":"<字符串>","cmd":"<命令>","fen":"<标准 FEN>","depth":<整数>}
  - id：每请求唯一字符串，原样回填到响应，用于请求/响应配对。
  - cmd：取值 "bestMove"（tournament 仅用此）；部分驱动另支持 "perft"/"legalMoves"
        （仅供 harness 自检，不影响对弈）。
  - fen：标准 6 字段 FEN（placement/side/castling/ep/halfmove/fullmove 空格分隔）。
        引擎须能解析 FEN 重建 GameState（§1 字段）。
  - depth：搜索深度，等同 §3 FindBestMove 的 depth 参数。

响应（引擎 → harness，stdout，逐行 JSON）：
  - 成功：{"id":"<同请求>","ok":true,"move":"<UCI 或 null>","score":0}
      · move：UCI 字符串，如 "e2e4"；升变后缀用小写字母，如 "e7e8q"（见 §8.1）。
      · move 为 null 当且仅当 GenerateAllLegalMoves(state) 为空（轮到走棋方被将死或
        无任何合法走法）。见 §8.3。
      · score：保留字段，当前所有驱动固定返回 0（真实评分非必需）。
  - 失败：{"id":"<同请求>","ok":false,"error":"<字符串>"}

编码与时序：
  - UTF-8；每条消息占一行（以 \n 结尾），不可 pretty-print、不可跨行。
  - harness 维护权威棋盘并负责：应用 move、校验 move 是否为本引擎的合法走法、判定
    将死/逼和/和棋。引擎驱动层**只实现"给 FEN → 返回 bestMove"**，不向 harness 暴露
    applyMove/isCheck。§3 中 applyMove 的责任归属见 §8.4。

--------------------------------------------------------------------------------
8. 已知一致性边界 / 歧义消除清单
--------------------------------------------------------------------------------
§8.1 升变字母大小写（消除"UCI 到底大写还是小写"的歧义）
  - 内部 Move.toString()（§1，控制台 SAN）升变用大写：=Q。
  - JSON-stdio 的 move 字段升变后缀用小写：e7e8q（所有驱动一致 tolower）。
  - 外部裁决（如 tournament/engine.mjs applyUci）两种大小写都接受；但引擎对外只输出小写。

§8.2 多个同分着法的平局裁决（消除"为何不同引擎步序列雷同、又为何有偏离"的歧义）
  - §3 FindBestMove 在根节点取"第一个达到最高 negamax 分"的着法，规范**未规定同分
    着法之间的 tie-break**。因此被选着法取决于各语言着法生成顺序与排序稳定性
    （OrderMoves 仅按 MoveOrderScore 降序；等分时次序未定义）。
  - 结论（一致性边界，非缺陷）：
      · 确定性引擎在相同局面/深度下，若着法生成顺序一致，会输出逐字节相同的着法——
        战报中出现"步序列雷同"属预期，不代表实现错误。
      · 若两引擎在某局面"最优着法集合"相同却各自选了集合内不同成员（取决 tie-break），
        该偏离**不构成移植缺陷**，只说明 tie-break 不同。要判定是否真错，须用
        tournament/reference_search.mjs 计算全窗口根分，确认差值是并列最优（TIE）还是
        严格劣着（MISTAKE）。见 tournament/engine_parity_audit.mjs。

§8.3 无合法走法时的语义
  - move:null 仅表示"轮到走棋方无合法走法"。harness 据此结合 isCheck 判定将死或逼和；
    引擎本身不区分二者，也不应返回除 null 外的占位值。

§8.4 applyMove / 合法性校验的责任归属
  - §3 的 ApplyMove、IsInCheck、IsCheckmate 等是**引擎内部**规则库函数，用于引擎自身
    搜索与自测。外部 harness/tournament 不依赖引擎暴露这些函数：它用自己独立的规则引擎
    （如 tournament/engine.mjs，perft 黄金值自检通过）重建棋盘、应用走法并校验合法性，
    从而**额外捕获引擎移植缺陷**（若某引擎返回非法 UCI，外部裁决判其该局负）。

§8.5 GetPositionKey 的过路兵编码（与严格 FEN 的差异，须知晓）
  - 按 §1，positionKeys/GetPositionKey 仅在 HasLegalEnPassant 为真时编码 ep 格，否则为
    "-1,-1"。这是本规范的刻意选择（与严格 FEN 始终编码双步兵 ep 目标略有差异），旨在
    避免"不可吃过路兵却改变局面键"的伪重复；三次重复判和据此进行。

§8.6 控制台 CLI 与驱动协议是两条独立入口
  - §4 的 test/selfplay/bench/play 是引擎独立运行入口；§7 的 JSON-stdio 是外部 harness
    驱动入口。两者共享 §1–§3 的引擎核心，但互不调用、互不依赖。
