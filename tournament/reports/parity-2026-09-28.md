## 根因：规范未定义同分着法的取舍

`lab/port_spec.txt` §3 只规定了 `MoveOrderScore`（吃子优先，MVV-LVA），
从未规定分数相同的走法之间如何排序。根节点用严格大于更新 `bestScore`，
于是**同分着法中排在最前面的那个胜出**——而"排在最前"取决于两个规范没定义的东西：
① 走法生成的遍历顺序；② 该语言排序算法是否稳定。

| 引擎 | 语言 | 排序实现（语义） | 源码证据 |
| --- | --- | --- | --- |
| ts | TypeScript | 编译为目标 JS 的 Array.sort — 稳定 | TsChess\chessAI.ts:147  `moves.sort((a, b) => AIEngine.MoveOrderScore(b) - AIEngine.MoveOrderScore(a));` |
| js | JavaScript | Array.prototype.sort — 稳定（ES2019 起语言规范要求） | JsChess\chessAI.js:146  `moves.sort((a, b) => AIEngine.MoveOrderScore(b) - AIEngine.MoveOrderScore(a));` |
| py | Python | list.sort — 稳定（Timsort） | PyChess\chess_ai.py:164  `moves.sort(key=AIEngine.move_order_score, reverse=True)` |


观察到的分歧只发生在 VB.NET 与 Go 上——两者都是**不稳定排序**语言；
而 ts / js / py 这群使用稳定排序的引擎之间 0/26 完全一致，也与基准一致。
这与"排序稳定性决定同分取舍"的解释完全吻合。

**结论：这些分歧不是移植缺陷，而是规范本身不完整。**
若要让六个语言的引擎逐着法完全对齐，建议按此优先级补充 `port_spec.txt`：

1. 明确要求 **stable sort**（Go 用 `sort.SliceStable`，VB 用带次序键的稳定排序，C++ 用 `stable_sort`）；
2. 并规定走法生成按 `row → col` 升序遍历，使稳定排序后的次序唯一确定；
3. 在上述都落到位前，作为一种更省事的替代：只对根节点增加确定的次级排序键（如 `from/to` 代数序）。

**本机限制（未做的事，如实记录）**：本机没有 Go 工具链、没有 .NET SDK（只有 Microsoft.NETCore.App 6.0.8 运行时）、没有 java.exe，
所以无法重新编译 `gochess_driver.exe` / `VBChessDriver.exe` 来验证"改成稳定排序后分歧消失"。
上述结论的依据是 full-window 分数等价 + 源码层面对各语言排序实现的证据，**没有做重新编译验证**。
